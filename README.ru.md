Chessemag — это современная, расширяемая многопользовательская платформа для игры в шахматы, созданная с использованием Go (Golang) и чистого JavaScript на фронтенде. Платформа поддерживает классические шахматы 8x8, а также современные варианты (10x10, 12x12), подбор игроков в реальном времени, рейтинговые игры на основе ELO и интерактивную историю партий.

Этот проект разработан как надежная основа для тех, кто хочет создать пошаговую многопользовательскую игру в реальном времени или расширить шахматное приложение новыми правилами и пользовательскими досками.

## Возможности

* **Многопользовательское ядро:** Игровой процесс в реальном времени через WebSockets с надежным управлением соединениями и периодами ожидания переподключения.
* **Подбор игроков (Matchmaking):** Автоматизированная система очередей, поддерживающая как обычные, так и рейтинговые режимы в зависимости от размера доски и контроля времени.
* **Рейтинговая система:** Система рейтингов на основе ELO, зависящая от формата игры (например, 8x8 10-минут, 10x10 15-минут).
* **История игр и анализ:** Детальная запись каждого матча с поддержкой пошагового воспроизведения, сохранения визуального состояния и нотации ходов.
* **Расширяемый игровой движок:** Реестр игр на основе интерфейсов (`core.Registry`), который позволяет легко добавлять новые размеры досок или совершенно новые варианты игр без переписывания ядра.
* **Настраиваемый фронтенд:** Игроки могут загружать или выбирать собственные фигуры, текстуры досок и фоны, которые синхронизируются и сохраняются в истории их игр.
* **Интерактивный чат:** Чат со стикерами-эмодзи во время игры.

## Стек технологий

### Бэкенд
* **Язык:** Go (Golang)
* **Веб-фреймворк:** [Gin](https://gin-gonic.com/)
* **База данных:** PostgreSQL с [GORM](https://gorm.io/)
* **Реальное время:** WebSockets ([gorilla/websocket](https://github.com/gorilla/websocket))
* **Аутентификация:** JWT (JSON Web Tokens)

### Фронтенд
* **Язык:** Vanilla JavaScript, HTML5, CSS3
* **Сборщик:** Vite
* **Логика шахмат/UI:** Пользовательская реализация для современных досок, использующая модифицированный `chessboard.js` для рендеринга классических досок 8x8.

## Начало работы

### Требования

* [Go](https://go.dev/doc/install) (версия 1.20 или новее)
* [Node.js](https://nodejs.org/) (для зависимостей фронтенда и Vite)
* База данных [PostgreSQL](https://www.postgresql.org/)
* [Docker](https://www.docker.com/) и Docker Compose (опционально, но рекомендуется для быстрой настройки)

### Переменные окружения

Создайте файл `configs/.env` в директории `chess-monolith`. Вы можете создать его со следующей структурой:

```env
PORT=8080
DB_DSN=host=localhost user=postgres password=postgres dbname=chess_db port=5432 sslmode=disable
JWT_SECRET=your_super_secret_key_here
FRONTEND_DIST_DIR=frontend/dist
```

### Локальная разработка

1. **Установите зависимости бэкенда**
   ```bash
   cd chess-monolith
   go mod tidy
   ```

2. **Настройка базы данных**
   Убедитесь, что ваш экземпляр PostgreSQL запущен и соответствует `DB_DSN` в вашем файле `.env`. Примените миграции схемы:
   ```bash
   make migrate-up
   ```

3. **Сборка фронтенда**
   ```bash
   cd frontend
   npm install
   npm run build
   cd ..
   ```

4. **Запуск сервера**
   ```bash
   make run
   # Или используя go run напрямую:
   # go run cmd/server/main.go
   ```
   Приложение будет доступно по адресу `http://localhost:8080`.

### Использование Docker

Чтобы запустить весь стек (База данных + Приложение) через Docker Compose:

```bash
cd chess-monolith
docker compose up --build
```
Это автоматически запустит PostgreSQL и бэкенд на Go. Примечание: вам все равно нужно убедиться, что фронтенд собран в `frontend/dist` перед сборкой Docker-образа, если вы хотите, чтобы его раздавал бинарный файл Go.

## Архитектура и структура кода

Проект следует архитектуре модульного монолита, разделяя зоны ответственности на отдельные пакеты.

```text
chess-monolith/
├── cmd/
│   └── server/          # Точка входа в приложение (main.go)
├── configs/             # Конфигурации окружения
├── frontend/            # Фронтенд-приложение на Vanilla JS (Vite)
├── internal/            # Основной код бэкенда
│   ├── game/            # Управление состоянием игры, репозиторий БД и HTTP транспорт
│   │   ├── core/        # Основные интерфейсы игры и общая логика доски
│   │   ├── modes/       # Специфичные наборы правил (classic, modern10, modern12)
│   │   └── session/     # Управление активными игровыми сессиями в памяти
│   ├── matchmaking/     # Система очередей и логика подбора оппонентов
│   ├── users/           # Аутентификация пользователей, профили и логика рейтинга ELO
│   └── ws/              # WebSocket хаб, клиентские соединения и маршрутизация сообщений
├── migrations/          # Скрипты миграции базы данных PostgreSQL
├── pkg/                 # Переиспользуемые утилиты
│   ├── ebox/            # Пользовательская обработка ошибок
│   ├── elo/             # Логика расчета рейтинга ELO
│   └── jwtutil/         # Генерация и валидация JWT
└── Makefile             # Автоматизация задач (build, run, migrate)
```

## Как расширить игру

### Добавление нового режима игры (например, Шахматы-960, нестандартный размер доски)

Платформа построена вокруг `core.Registry`, который сопоставляет названия режимов игры с их специфическими наборами правил (`core.Ruleset`).

1. **Создайте реализацию Ruleset:** Реализуйте интерфейс `core.Ruleset` для вашего нового режима в новом пакете в `internal/game/modes/`.
   ```go
   // internal/game/modes/mycustommode/mycustommode.go
   type CustomRuleset struct {}
   func (r *CustomRuleset) ValidateMove(board *core.Board, move core.Move, playerColor core.Color) error { ... }
   func (r *CustomRuleset) CheckGameStatus(board *core.Board, currentPlayer core.Color) core.GameStatus { ... }
   // ... реализуйте остальные методы интерфейса
   ```
2. **Зарегистрируйте режим:** Экспортируйте функцию `Register` и вызовите ее во время инициализации сервера в `cmd/server/main.go`.
   ```go
   // cmd/server/main.go
   func initGameRegistry() *core.Registry {
       registry := core.NewRegistry()
       classic.Register(registry)
       modern.Register(registry)
       mycustommode.Register(registry) // Зарегистрируйте ваш новый режим
       return registry
   }
   ```
3. **Обновите Matchmaking на фронтенде:** Убедитесь, что ваш фронтенд может запрашивать подбор игроков для этого нового названия режима через `WebSocketMatchmakingStrategy` в `lobby.js`.

### Модификация фронтенда

Фронтенд использует Vite для сборки. Основная логика находится в `frontend/js/`.
* `lobby.js`: Управляет состоянием UI, подбором игроков, настройками пользователя, просмотром истории и делегированием событий WebSocket.
* `board.js`: (Если применимо) Расширяет или управляет рендерингом нестандартных размеров досок наряду с классическим `chessboard.js`.
* `socket.js`: Управляет жизненным циклом WebSocket соединения и форматированием полезной нагрузки.

После изменения файлов в `frontend/`, запустите `npm run build` в директории `frontend/`, чтобы обновить папку `dist/`, которую раздает бэкенд на Go.

## API Документация

Хотя игровой процесс в основном происходит через WebSockets, приложение предоставляет REST endpoints для аутентификации и истории.

* **POST** `/api/register` - Создать новый аккаунт пользователя.
* **POST** `/api/login` - Аутентификация и получение JWT.
* **GET** `/api/me` - Получить текущий профиль пользователя и рейтинги (Требуется Auth).
* **GET** `/api/games` - Получить историю игр для текущего пользователя (Требуется Auth).
* **GET** `/api/games/:id` - Получить детальное состояние и историю ходов для конкретной игры (Требуется Auth).
* **GET** `/api/leaderboard` - Получить лучших игроков для конкретного режима/размера доски.
